## 1. Выбор размеров виртуальных машин

### API Gateway (2 vCPU, 4 GB RAM)

API Gateway (Kong) выполняет маршрутизацию и авторизацию запросов. Это в основном работа с сетью и небольшие вычисления (JWT-верификация). 2 vCPU достаточно для нескольких тысяч запросов в секунду. 4 GB RAM с запасом для Kong и его плагинов.

Два инстанса — минимум для отказоустойчивости: при падении одного балансировщик продолжает отправлять трафик на второй.

### Брокеры Kafka (4 vCPU, 8 GB RAM)

Kafka интенсивно использует ввод-вывод и сеть. Процессор нужен для сжатия сообщений и репликации. 8 GB RAM — для кэша страниц: Kafka активно использует кэш операционной системы для ускорения чтения.

Три брокера — минимум для кворума: при падении одного двое оставшихся продолжают работу. Нечётное число — требование алгоритма выбора лидера (Raft/ZooKeeper).

### ВМ приложений доменов (2 vCPU, 4 GB RAM)

Сервисы доменов (Clinical API, Fintech API и т.д.) — это бизнес-логика и запросы к БД. Основная нагрузка — на PostgreSQL, а не на ВМ приложения. 2 vCPU и 4 GB RAM достаточно для начала; при росте нагрузки масштабируется через `app_vm_count`.

### Bastion (1 vCPU, 2 GB RAM)

Bastion выполняет только SSH-проксирование. Практически никакой вычислительной нагрузки. Минимальный инстанс достаточен и дёшев.

### Мониторинг (2 vCPU, 4 GB RAM)

Prometheus собирает метрики с 10+ ВМ и хранит их временные ряды. 4 GB RAM нужны для хранения метрик в памяти (TSDB Prometheus работает in-memory). Если метрик станет больше, сначала увеличивается RAM, затем — рассматривается Victoria Metrics как более эффективная альтернатива.

## 2. Выбор размеров дисков

### Kafka: 100 GB SSD на брокер

Kafka хранит сообщения на диске с настраиваемым временем хранения. 100 GB при среднем потоке событий в компании (медицина, финтех, операции) хватит на 7–14 дней хранения. SSD обязателен: задержка записи напрямую влияет на throughput всей шины.

Диск отдельный от системного — если Kafka заполнит диск логами, ОС не упадёт.

### PostgreSQL: 50 GB SSD на кластер

Каждый домен получает 50 GB. Для операционных данных (не архивных) этого достаточно на старте. Рост данных легко отслеживать через мониторинг и увеличивать диск через `terraform apply` без пересоздания кластера.

SSD обязателен для PostgreSQL: случайный ввод-вывод (характерный для реляционных БД) на HDD в разы медленнее.

### Мониторинг: 50 GB HDD

Prometheus хранит метрики с retention 15 дней по умолчанию. 50 GB HDD достаточно и дешевле SSD в 3–4 раза. Последовательная запись метрик не требует низкой задержки — HDD справляется.

## 3. Настройки NAT

NAT-шлюз позволяет ВМ в приватных подсетях выходить в интернет без публичного IP:

- Скачивать пакеты при инициализации (cloud-init)
- Обращаться к внешним API (платёжные системы в финтехе, внешние медицинские базы)
- Получать обновления безопасности

Без NAT приватные ВМ полностью изолированы от интернета — это безопаснее, но требует отдельного зеркала пакетов внутри сети. Для начала NAT — правильный баланс безопасности и удобства.

Все приватные подсети используют одну таблицу маршрутов с маршрутом через NAT. Публичная подсеть NAT не нужна — балансировщик сам имеет публичный IP.

## 4. Обоснование пяти замечаний Checkov

| Замечание                                      | Обоснование                                                                                                                                                                                         |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Bastion имеет публичный IP (CKV_YC_2)          | Архитектурное решение: Bastion — единственная точка SSH-входа. Без публичного IP невозможно подключиться снаружи. Группа безопасности ограничивает доступ конкретным IP.                            |
| Monitoring без группы безопасности (CKV_YC_11) | Мониторинг в изолированной подсети управления. Недочёт — добавить группу безопасности в следующей итерации.                                                                                         |
| Бакеты без явного KMS-шифрования (CKV_YC_3)    | Yandex Cloud шифрует данные at-rest по умолчанию. Явный ключ KMS нужен только при требовании BYOK. Для PHI Vault рекомендуется добавить `yandex_kms_symmetric_key` в следующей версии конфигурации. |

Замечания задокументированы, не являются критическими уязвимостями и не блокируют развёртывание.
